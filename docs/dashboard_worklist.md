# Dashboard worklist (post-v1)

Tracked enhancements for the dashboard and its Documentation tab, to address after v1 is finalized. This is distinct from the framework's data/measurement future work (see `governance_framework_master.md` -> "Future enhancements (post-v1)") and from the running decision log (`framework_decisions.md`). Dashboard/UI enhancements go here.

## Open

- **Source links per metric.** Make each metric's source a clickable link in the Documentation tab (and reusable elsewhere the source label appears). No usable URLs exist in the data today: `instructions_data_maintenance.md` holds only ~12 scattered data-download URLs (in prose, several access-gated), and `data/processed/source_registry.csv` (72 sources) has no URL column. Plan, kept single-sourced: add a `url` column to `source_registry.csv` (no new file; use homepage URLs, which are stable, rather than deep download links, which are not), populate it, establish a clean metric->source join key (verify that `metric_dictionary.py` / the metric metadata carries a `source_id` matching the registry rather than fuzzy-matching the free-text `src` label), then read it into `meta` and render the links in `renderDocs`. Flagged as the one genuinely hand-maintained table if built, hence deferred from v1.

- **Human-readable concept and category descriptions.** The Documentation tab currently parses each concept's description live from the master doc's `**Scope:**` line, single-sourced from `governance_framework_master.md` at build time. Those lines are written as internal methodology notes (placement caveats, exclusions, jargon), so they read as working notes rather than reader-facing prose. Rewrite them for a general reader, and add category-level descriptions (the master defines none today, so the category sections currently show no description). Keep it single-sourced: either polish the master's `Scope` lines in place, or add a dedicated reader-facing field the pipeline parses, so the tab stays in sync from one source.
